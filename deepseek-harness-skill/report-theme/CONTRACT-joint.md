# CONTRACT-joint —— 三技能联合报告协同契约（v0.5）

> 单一事实源：百宝袋（bai-bao-dai）× 揽风云（lan-feng-yun）× 破虚妄（po-xu-wang）三技能联合任务
> 的**衔接约束**。各技能内部语义留在各自 SKILL.md；独立使用路径不加载本文件、零影响。
> 入口工作流关系见 skills/san-he-yi/SKILL.md（薄入口只讲顺序，不重复本文件细则）。

## 1. 硬性流程（禁止绕过流水线）

- 联合任务必须真实执行百宝袋流水线：`collect → normalize → (check 事实还原) → opinion`，再由 `build_report` 装配。
  **禁止以 LLM 手写 HTML 顶替流水线**；各步以文件参数串联，后一步输入缺失即停。
- 三平台（知乎 + 微博 + 小红书）真实采集为硬性要求；不得以"搜索摘要足够 / 抓取受限 / 估计网络不通"静默降级。
- 阻隔分类码：`P` 权限 / `C` 凭证 / `E` 环境。
  - P → 以 `danger-full-access` 升级重试同一条命令或向用户申请授权；
  - C → 向用户索取（扫码登录 > cookie），成功后重跑；
  - E → 如实报告 + 给出替代路径（dsh-ssh 远端、存档站、请用户提供原文）并询问用户。
- **任何跳过/降级必须走到「用户确认」或「用户拒绝后如实披露」**，写入合规账本（§4）。禁止单方判定后继续。
- **④ 汇合是唯一能看到全部工件的阶段**：装配完成 ≠ 交付完成，须再跑一次数据对账（§10）。
  门禁 0 error 只证明"报告形态合规"，不证明"报告与数据自洽"——两者互相不可替代。

## 2. 证据隔离与来源分级

- 第 3 章（汇编）的转述 = 待核查对象，不是证据；第 4 章（核查）不得引用第 3 章自身编号作证据（禁自我循环）。
- 每条裁决标注证据等级（facts.json `claims[].evidence_level`）：
  `1 官方文件/本人账号原文 ＞ 2 权威媒体全文 ＞ 3 转载引文 ＞ 4 搜索摘要/标题层`。
- **等级量的是"这条证据本身是什么形态"，不是"本次核验取得了什么"**（v0.5 澄清）：
  「3 转载引文」的成立条件是**该证据为他人对原始发布物的转述**（引文经转载、经记者转述二手口径）；
  **"我这次没抓到原文全文"不构成降级理由**——那是归档完整度问题，记在 `sources.json.fetched_file` 缺位上，
  不得改判证据等级。首次登记时将「获取方式」与「证据形态」混为一谈，
  会使一手受访、基层口径、本人自述等**最难取得原文**的强证据被系统性降级（实测 22% 断言挂降级）。
- **证据条目里不得写抓取动作**（"（原文抓取）""（已下载）"等）：证据描述只写来源与其自身日期；
  "我抓过/我归档了"由 `sources.json.fetched_file` 承载（门禁 G13）。
- 展示规则：verdict=「真实」且 evidence_level∈{3,4} 时，报告裁决显示「报道属实（原文未核）」
  （facts.json 语义不变，渲染层降级，由 build_report 执行）。
- **信源独立性按转载簇计，不按 URL 计**：同一稿件的门户镜像只计 1 个独立信源；
  「多源确认」的 N 指独立稿簇数。"一条权威稿被三家转载"不是三个来源，不得据此判「多源一致」。
- **来源分级（A/B/C）的唯一口径**（v0.4 统一，取代各技能的旧定义；与上面的 evidence_level 是两件事，
  互不替代：前者给**来源**定级，后者给**裁决**定证据强度）：

  | 级 | 含义 | 例子 |
  | --- | --- | --- |
  | A | 官方一手（公文/通报/裁决/处罚决定）+ 当事人本人账号原文 | 警方通报、法院文书、本人微博原文 |
  | B | 权威媒体全文（官媒评论、通讯社、全国性市场化媒体、专业法律媒体） | 人民锐评、法治日报、极目新闻、南都 |
  | C | 转载、自媒体、平台语料样本（含所有自动采集的 UGC） | 门户转载稿、公众号分析、微博/小红书样本 |

  · 自动采集帖默认 C；**转载稿按原始出处定级**（如"新浪财经转载观察者网"应为 B，而非因门户而记 C）。
  · 分级分布若出现 `A=0`，而正文实际引用了官媒原文或本人账号原文，属**分级未落地**，须修正分类而不是照抄统计行。

## 3. 标记域与裁决词

- ▲/●/△ 仅用于**具体数字/数据口径**（揽风云 4.4 既有规则，此处为联合报告执行声明）。
- 裁决 chip 只用裁决词：真实 / 部分真实 / 失实 / 证据不足（外加渲染降级变体「报道属实（原文未核）」），
  **chip 内禁止混入 ▲●△**（门禁 G3）。
- 否定性主张（"未见 / 未回应 / 未表态"类）默认裁决「证据不足」并注记"检索未见支持证据"；
  仅当存在权威渠道明确否定声明时可判「真实」（门禁 G5）。
  注记须写明**检索边界**（检索了哪几类渠道、截至哪一时点），"检索未见"不是一句免责话术。
- **否定性主张必须以否定句登记**（v0.5）：`claim` 写「截至 X 未见 Y」，**禁止**用肯定句登记
  （"某机关已作出通报"）而把"尚无"写进 `short_title`——同一张卡里正文、标题、裁决三向相反，
  读者按标题读成"确认没有"，按正文读成"确认有了"（门禁 G13）。

## 4. 采集合规账本（compliance.json）

装配时以 `build_report.py --joint --compliance data/{event_id}/compliance.json` 渲染进第 7 章
（`<table class="compliance">`）；schema：

```json
[{"platform": "weibo", "status": "已采|跳过|降级", "block": "P|C|E|null",
  "escalated": true|false, "user_confirmed": true|false,
  "alternative": "dsh-ssh|存档站|用户提供原文|null", "note": "…"}]
```

- 状态非「已采」且无用户确认 = 不合规（门禁 G1）。
- 账本记的是**采集**；语料治理阶段的**剔除**另计：相关度过滤剔除量、剔除占比与其构成
  （哪一平台、帖文还是评论）须写入覆盖声明，且任一平台剔除占比 >30% 时同时写进摘要（门禁 G8）。
  语料治理必须走 `skills/bai-bao-dai/scripts/relevance_gate.py`，产物名固定为
  `normalized/data.relevant.jsonl`（留下的）与 `normalized/excluded.jsonl`（剔除的）——
  禁止临时脚本另生成别的文件名（`data_filtered` / `event_only` / `data_relevant` 等历史别名仅供门禁兼容读取，不再新写）。
- **对抗式证据优先采**：采集检索词不得只用指控方口径（如「X 被指 Y」）；应至少再加一组中立词与一组反方词，
  检索词清单写入报告方法论章。立场占比会随检索词偏移，读者必须能看到检索式是什么。
- 联合报告须在 `<head>` 带 meta：`<meta name="dsh-report" content="joint;contract=joint-v0.4">`
  （build_report `--joint` 自动注入；手写 HTML 须自行声明，门禁 G2）。

## 5. 统一时效与情景句

- 事件状态 = 进行中：走势/舆论章只允许情景句（"若官方不回应则 X；若双方继续发文则 Y"），
  禁止确定性曲线表述（回落 / 平息 / 结束等，门禁 G6）；并注明为动态快照。
- 成稿时间晚于信息截止 > 2 小时，须记录期间是否做过增量检索及结果。
- 背景/历史坐标（距今 > 1 年）须带时效核验标注：数据年份 + 其后是否检索到政策/事实变更 +「系既往回应 / 非现状」。
- **单一时点采集不得支撑时序结论**：只有一个采集日的语料，其"按日期分布"只能读作"各发布日占比"，
  不得表述为舆论演变、焦点位移或趋势（门禁 G6 同源）。

## 6. 断言登记册与前置扫描（执行一次）

- 核查阶段输入 = 汇编正文的断言清单（破虚妄阶段 2 本会做断言抽取，登记册天然形成，不新增流程）。
  F 表须覆盖登记册每条或给出显式豁免；豁免清单单列于覆盖声明。
- **哪些主张不进断言登记册（v0.5）**：断言登记册只收**可裁决真假的事实陈述**。下列四类**不登记为事实断言**：
  ① 评价性判断（好坏、轻重、是否过分）；② 法律/专业定性（"不构成性骚扰""涉嫌寻衅滋事"）——
  其**可核部分**（"某律师公开表示…"）仍可登记，但裁决对象是"该意见被如实转述"，
  不是"该法律结论成立"；③ 因果推断（"症状系该次触碰造成"）——登记为**主张归属**（谁在主张），
  因果本身不裁；④ 证明力评价（"这些数字可用以证明其为炒作"）。
  ③④ 归入观点辨析（§11 `opinion_analysis`），不入登记册、不占裁决词。
  首次登记时把律师意见判成「真实」，使读者读成"法院/权威已作认定"，即由此而来。
- **不得把强弱悬殊的子主张合并成一条断言**：一条断言只承载一个可独立裁决的主张。
  **可判据（v0.5）**：若一条 `claim` 内部含两个以上**可分别给出不同裁决词**的子句，
  即属合并，须拆条；`short_title` 只能压缩其中一条时，也说明该条本就该拆。
  合并会使强项被弱项拖入「证据不足」，或让一个「真实」默默覆盖四五件事（门禁 G13 列条待人工确认）。
- 诱因三问（① 有无触发事件；② 主张是否只有被媒体截取的半句；③ 有无断章取义警示信号）
  在登记断言时执行一次，结论写入 facts.json `context` 字段，供各阶段读取，不重复执行。
- **裁决必须回写叙事（v0.5）**：裁决粒度是"整条断言"，叙事粒度是"整段文字"，两者不重合。
  故凡 `verdict ∈ {证据不足, 失实}` 的断言，其**具名数字 / 引语 / 定性短语**不得在第一、二、五章
  以直陈形式出现——须带「网传 / 未经核实」限定，或改由第四、五章引用编号指向该条（门禁 R5）。
  首次联合报告即出现"第三章判 77 元证据不足、第二章时间线仍写『赔付 77 元』"的同一报告自相矛盾。

## 7. 交付质量门

- **唯一产出方 = ②揽风云**（其 SKILL.md「阶段 6：主体档案」）：主体识别/分层、时间子线、回应链均由 ② 从自身已产出的时间线素材重投影；schema 与判据见该技能文档，本文件不重复方法。
- **③破虚妄只引用、不重裁**：`actors.json` 的 `claims` 只写第三章断言编号；裁决词由装配端从 `facts.json` 登记册自动补齐（`build_report --actors` 读 `--facts` 的 `claims[].verdict`）。③ 不为主体档案单独复核，也不为每个主体重跑一遍核查；档案若暴露**新**主张，走既有登记册流程补登。
- **④百宝袋只装配、不代写**：`--actors` 传**对象**形态挂第二章末（h3 自动编号 x.1）；传**数组**形态仍走旧「角色小词典」（向后兼容 v0.2.6，挂第一章末）。
- **防漂移两条硬规则**（与 §2 证据隔离同级）：
  1. **只投影不新增**——档案节点必须能在第二章时间线找到对应条目；档案不得成为第二个叙事源。
  2. **只引用不判定**——`claims` 必须存在于断言登记册；裁决词以登记册为唯一来源。
- **静默须显式登记**：主体「未见表态 / 无官方声明」以 `kind: "quiet"` 登记，与"未覆盖（空单元格）"区分，避免把漏采伪装成事实性沉默（承 §4 合规账本精神）。

## 9. 舆论口径与立场卡组工件（v0.3）

### 9.1 四层口径（opinion.py 默认行为）

单标签聚类把「无命中」统一记为「无关/其他」。若把它作为一个立场画进条形图、环形图、趋势折线，
头号「立场」就会长期是它——**那是把方法缺陷当成数据结论**。故分工如下：

| 层 | 定义 | 是否进立场分母 |
| --- | --- | --- |
| A 个人表达样本 | 命中立场词典的个人账号帖文/评论 + 知乎回答 | **是**（占比分母） |
| B 机构/媒体帖 | 机构账号帖（**仅按账号名机构特征词判定**） | 否 |
| C 未归类残差 | 未命中词典者，另出诊断 | 否 |
| D 治理剔除噪声 | 上游语料治理剔除的无关内容 | 否（仅计数） |

- 机构帖是信息供给方而非舆论主体，把「报道了某立场」当成「持某立场」，会让「高赞代表」被媒体转述帖占满。
  平台对账号名做匿名化（`潇***报`），故 B 层是**识别下界**；宁可偏小（保守），不可偏大（污染分母）。
- **分类结果必须抽检才能引用，抽检须落盘为工件**（v0.4）：工件为
  `data/{event_id}/spotcheck_{stance,rule,unclassified}.json`，由 `bai-bao-dai/scripts/spotcheck.py`
  生成判读单（固定 seed 分层抽样）→ 人工逐条判读 → `--apply` 计算并回写 `opinion.json` 的 `spotcheck` 字段。
  · 三种核各有分工：stance 核校正**标签确定性** · rule 核校正**占比上界** · unclassified 核回答**漏了多少**。
  · **误判率 >30% 的立场不得作为主结论呈现**（门禁 G11）；未识别层须给出"含立场表达"的估计与 95% 区间。
  · 未完成抽检时，报告只能把占比标为"未校正"，不得出现"主流 / 压倒性"类措辞。
- **「未识别」≠「与事件无关」**（v0.4）：单标签聚类的"无命中"只表示**词典没命中**，相关性已在上游语料治理判过。
  报告禁止使用「无关/其他」这一命名（门禁 G10）；未识别残差须分段披露（纯反应 / 原样转述 / 未分类），
  且**只有机械可判的段可下结论**——"未分类"段必须抽样人工核后才能描述其构成，不得写成"不含立场表达"。
- **占比必须与两个覆盖率同时呈现，且不得据此下结论**（门禁 G7/G10）：
  `coverage_rate`（A / 全部语料，保守下界）与 `coverage_of_judgeable`（A / 可判集合，可判集合 = A + 规则层独有 + 未分类段）。
  只给前者会把覆盖率系统性压低——分母里含几百条本就不含立场表达的反应/玩梗/轶事。
  占比只读作「可识别立场内部的相对结构」，覆盖率低于 30% 时不得使用"主流 / 压倒性 / 舆论主体"类措辞。
- **规则层（口语判据）与词典层并列不合并**：词典层是可复现下界，规则层是上界。
  正则判不了立场（实测误判率 2–3 成），故规则层**必须附人工抽检误判率**才可作为结论依据；
  未抽检时只能呈现为占比上界（门禁 G10 同源）。
- 残差诊断（`residual.diagnostics`）是修订词典的**唯一合法依据**：`grams_outside_vocabulary` 给出
  「残差高频词 − 立场词表」的差集；**不得依据 `top_samples` 补词**——高赞多为媒体转述帖，方向是反的。
- 若残差高频词以事件描述性名词为主，说明未归类的主体是口语化短句表态，**继续扩大词典是错的**，
  应如实披露覆盖率并说明需语义层（分层抽样人工标注），而不是加词压比例。
- 词典修订次数用尽仍不达标时，允许的替代路径只有"如实披露 + 标注层"，**不得改口径、改分母或改成"方向性参考"**。

### 9.2 立场卡组（`stance_cards.json`）

- **唯一产出方 = ②揽风云**（其 SKILL.md「阶段 7：立场卡组」）：把 opinion.py 聚类出的每个立场写成抽象逻辑链。
- **③破虚妄不介入**：卡组不含裁决词；`steps` 中的引用编号指向来源索引，不指向 F 表。
- **④百宝袋只装配**：`build_report.py --stance-cards` 渲染；**缺该工件时不回退生成引语卡**，
  只给一行提示——「缺工件宁可不渲染」优于用别的章节素材填坑。
- 硬性限制（单步 ≤14 汉字、3–5 步、`note` ≤55 字、引语不进卡内）见 report-theme 同名条目，超限由 W15 提示。

### 9.3 引用闭环（v0.3 内建于装配端）

时间线节点 `ref` 字段 · 断言 `claims[].ref` / `evidence[].ref` · 卡组 `steps`/`note` 内 `[N]` ·
高赞代表按样本 `ref_url` 自动挂号。样本 `ref_url` 由 opinion.py 解析（评论回指父帖）。装配端先收录被引用地址
再渲染第五章，故引用必然落地。门禁：W1 双向一致 · W16 高赞代表引用率 · E6 断言可溯源。

## 10. 数据对账（v0.4，交付前一次，机器可判部分由 `--data` 自动执行）

报告形态合规与数据自洽是两件事。以下四条是硬约束；不通过即为 error，回退到对应阶段修复，
**不得以改措辞、加注脚、标"方向性参考"的方式消解**。

1. **一数一源、内部同值**：同一指标在摘要、KPI 卡、各章中必须同值。
   凡由脚本自动生成的字段（时间跨度、采集量、占比），必须与人工撰写处的相应表述一致；
   摘要写的天数与 KPI 卡的时间跨度必须相容（门禁 R1/R2）。
2. **语料不得越出事件窗口**：分析语料（`normalized/data_filtered.jsonl`）中不得存在早于事件起点的记录；
   评论按**自身时间**过滤，不得只按父帖相关度放行。发现即从分析语料剔除、重新聚类，并披露剔除数（门禁 R3）。
3. **「证据不足」须向语料反查**：判「证据不足」前，先在 `data_filtered.jsonl` 反查该断言的关键词，
   确认语料中确无记录（或记录不能构成证据），并在裁决理由中写明实际语料条数。
   裁决理由不得与语料规模明显不符（如语料中十余条记录却写"仅见单条帖文"）（门禁 R4）。
4. **独立信源数须可核**：chip=真实 的断言，去重转载簇后独立信源 <2 个时须带风险标注（门禁 G4b）；
   同一来源被多条断言反复引用时，"多源交叉"的表述不成立。

## 11. ②③产出工件契约（v0.5；只放 schema 本体，书写理由见各自 SKILL.md）

②揽风云、③破虚妄须向 ④ 交付下列工件。缺 schema 的工件此前只能由模型即兴发挥，是"时间线无年份 /
来源分级 0 条 A / 覆盖声明遗漏剔除量 / 冲突表整段消失"等缺陷的共同来源。字段名为**最小集**，可增不可改名。

> **③ 的 verify 九章在联合态的去向**（v0.5 定死，避免静默丢弃）：① 原始内容精要 → `context`；
> ② 事实断言清单 → `claims[]`；③ 核查结论 → `claims[].verdict`；④ 关键证据与来源 → `claims[].evidence[]`
> ＋ `sources.json`；⑤ 证据矛盾标注 → `claims[].conflicts`；⑥ 观点辨析 → `opinion_analysis`（④ 渲染为独立一章）；
> ⑦ 综合可信度评估 → 由 ④ 的覆盖完整性声明章承担（③ 不重复产出）；⑧ 方法论说明 → ④ 方法论章；
> ⑨ 核查时间戳 → `as_of` ＋ ④ 时间戳章。

```jsonc
// timeline.json —— 事件时间线（--timeline-milestones）
[{"date": "2026-08-26",              // 必填；一律 YYYY-MM-DD；区间写 "2026-08-26 ~ 2026-09-07"（两端带年）
  "type": "official",                // 必填；official|media|view|bg|quiet|check
  "tag":  "三次调解",                 // 必填；节点短标签（渲染为标签胶囊）
  "title": "街道调解室与派出所三次调解均未达成和解",  // 必填
  "text":  "……",                     // 必填；描述性正文
  "count": 0,                        // 选填；当日采集记录数。**缺省由 ④ 按语料按日回填**，②不必手写
  "ref":  "[1][2][3]"}]              // 选填；引用编号，渲染为可点击锚点
```

```jsonc
// sources.json —— 来源索引（--sources）
[{"name": "人民网·观点频道《人民锐评：四岁男童的肢体接触…》",  // 必填；媒体名 + 《标题》，
                                                              //   书名号内不得再出现「：」以外的分隔歧义
  "url":  "https://...",             // 必填
  "grade": "B",                      // 必填；A|B|C，口径见 §2（唯一口径）
  "type": "官方媒体评论（原文抓取）",  // 选填
  "fetched_file": "people_ruiping.txt",  // 选填；归档正文文件名（相对 sources/），
                                         //   有值则 ④ 渲染"已归档"标记，并使其可被读者回溯
  "used_as": [1, 2, 17]}]            // 选填；该来源被哪些断言/行引用（用于复用度统计）
```

```jsonc
// facts.json —— 断言登记册（③破虚妄；--facts）
{"event":   "长沙「4岁男童被指摸臀」事件",   // 必填；与 ① 的 event_id 对应
 "as_of":   "2026-09-10 23:30 (+08:00)",  // 必填；信息截止时点＝本轮核查的检索边界
 "context": {"诱因三问": {…}, "结论先行": "…"},   // 必填；§6 前置扫描结论，供各阶段读取，④ 不渲染
 "opinion_analysis": [                     // 选填；观点辨析＝verify 第 6 章的联合态落点
   {"id": "V1",
    "target": "当事人视频与后续报道的定性口径",   // 必填；被辨析的主张或文本
    "premise": "该主张成立所依赖、但未明说的前提",  // 必填
    "fallacy": "逻辑谬误（无则留空）",           // 选填
    "bias": "立场偏差（无则留空）",              // 选填
    "chain": "从证据到结论的推导链",             // 必填
    "conclusion": "结论",                       // 必填
    "claims": [1, 2]}],                       // 选填；关联断言编号（渲染为 #N 锚点）
 "claims": [
   {"id": "F1",
    "claim": "断言原文",                       // 必填；否定性主张**必须是否定句**（§3）
    "short_title": "≤24 字摘要",               // 必填；必须与 claim 同向（否定性主张不得写成肯定）
    "verdict": "真实|部分真实|失实|证据不足",     // 必填；只用这 4 个词（§3），不带括号后缀
    "evidence_level": "1|2|3|4",              // 必填；口径见 §2（量证据形态，不量获取方式）
    "reason": "裁决说明",                      // 必填；反证与"检索未见"写在这里
    "evidence": [{"source": "来源名 + 日期"}],  // 必填 ≥1；**只放支撑证据**，
                                              //   不得以「反证：/检索未见/现状：」开头（门禁 G13）
    "ref": "[1][2][3]",                       // 选填；编号须落在 sources.json 编号域内（④ 按 url 顺序编号）
    "conflicts": {"point": "冲突点",           // 选填；口径冲突**只用这一种形态**（门禁 G13）
                  "versions": [{"who": "来源", "value": "说法"}],
                  "resolution": "取舍与理由"}}]}
```

- ④ **只消费 `claims`**：`event` / `as_of` / `context` 是阶段间读物（供 ③④ 的模型读取），不渲染进报告；
  `opinion_analysis` 渲染为独立一章。

- **coverage.md（覆盖完整性声明）必含小节**：① 语料口径（原始采集 → 分析语料 → 剔除量 / 占比 / 平台与类型构成）；
  ② 信源结构（中央/地方/专业/境外各覆盖到什么）；③ 主体维度（哪些主体有直接材料、哪些只有转述）；
  ④ 地域与视角；⑤ 议题维度；⑥ 未覆盖项及原因。**①② 为机器可判项，缺失即门禁 G12 报错。**
- **viewpoint.md（视点综合）必含小节**：声量结构 · 各立场论证结构 · 少数派与对立观点 ·
  焦点转移（仅多日采集可写）· 未识别残留 · 场景推演。
  **文中不得出现与报告口径行冲突的硬编码数字**（覆盖率、条数、层数一律引用而不复述）。
- **actors.json / stance_cards.json**：schema 见 §8 / §9.2，本处不重复。
