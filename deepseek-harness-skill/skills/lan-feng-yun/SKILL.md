# 揽风云 — 信息汇编技能

## 目标

围绕用户指定主题，通过多源搜索与交叉比对，汇总整理信息，产出结构化报告。**不做事实真伪判断**（那是 `/破虚妄` 的职责），专注于"把信息找到、理清、呈现好"。

## 两条路径（先读这一节，决定后续读哪一半）

| 路径 | 触发 | 走哪些阶段 | 产出 |
|---|---|---|---|
| **独立使用** | 用户直接 `/揽风云` | 阶段 1–5 全部 | markdown / HTML / json 报告（按「输出规范」） |
| **联合任务** | 由 `/三合一` 编排（揽风云 × 破虚妄 × 百宝袋） | 阶段 1–5（素材层）+ 阶段 6/7（工件层） | `data/{event_id}/` 下的**工件**，schema 见 CONTRACT-joint §11 |

- **两条路径共用阶段 1–5**（搜索、聚类、去重、冲突消解、标注），差别只在**产出形态**：
  独立态产出报告正文；联合态产出**工件**（`timeline.json` / `sources.json` / `actors.json` /
  `stance_cards.json` / `coverage.md` / `viewpoint.md`）交给 ④ 装配。
- **联合态的接口以 `~/.dsh/report-theme/CONTRACT-joint.md` 为唯一事实源**（尤其 §11 工件契约、§2 来源分级）。
  本文档只讲方法与书写要求，**不重复 schema、不重复门禁编号**，避免两处漂移。
- 阶段 6 / 阶段 7 标注了各自在两种路径下的状态；**未标注"独立态"的产出，即为联合态专有**。

## 工作流程

### 阶段 1：解析需求

从指令提取：主题、截止时间、范围约束、深度。若主题涉及国际/境外视角，先读 `references/foreign-media.md` 再进入阶段 2。

### 阶段 2：首轮搜索

并行 **2–4 次** WebSearch，搜索词设计原则：
- 至少一次中文 / 一次英文（国际语境）
- 覆盖不同角度：官方通报、媒体报道、数据/统计、立场/反应、**现场照片/视频截图**
- 搜索词之间有明确区分度，避免高度重叠

首轮即确定广度，后续只做缺口补充。若搜索结果含 `zhihu.com` 链接，走知乎 API 路径（见 `references/source-fallback.md`）。

### 阶段 3：缺口识别与补充

对照首轮结果，按维度查缺：

| 维度 | 检查项 |
|------|--------|
| 事实 | 时间、地点、参与方、结果是否完整 |
| 立场 | 各主要相关方表态是否覆盖 |
| 来源 | 官方/权威媒体/行业分析是否均有 |
| 地域 | 国内/国际视角是否平衡 |
| 时间 | 最新进展是否到截止时间 |
| 因果与语境 | 诱因/触发事件是否查明；主张是否只有被媒体截取的半句；有无断章取义警示信号 |

针对缺口执行 **1–2 次**补充搜索。停止条件：核心信息 ≥2 独立来源交叉确认、各方立场已获取、无明显空白。总量控制在两轮以内。

### 阶段 4：信息组织与标注

#### 4.1 主题聚类（碎片 → 主题）

将搜索结果中的碎片事实按四个维度打标签：
- **事件**：属于哪个具体事件/子事件
- **主体**：涉及哪些组织/人物/群体
- **争议点**：存在分歧或不同说法的问题
- **时间阶段**：是背景、进展、还是最新动态

然后聚类成 **2-4 个主题**，每个主题必须能用一句话说出中心（如"OPPO 文案事件：道歉 → 争议 → 官媒评论三阶段"）。聚类规则：
- 同主题碎片合并为一节，节内按时间或逻辑排列
- 无法归入任何主题的孤立碎片 → 并入「其他/补充」小节，并说明为何孤立
- 聚类不是标签堆砌——每个主题必须有一个**可检验的中心判断**（读者读完能复述"这节讲了什么"）

#### 4.2 去重合并（重复 → 合并）

同一事实主张被多个来源重复报道时，合并为一条，标注 `多源确认（N 家）[编号]`。规则：
- 一 URL 一编号，多源交叉确认标注多个编号（如 `[1][3]`）
- 合并后保留首次出现的编号顺序
- 合并时若各来源措辞/数字有出入，转入 4.5 冲突消解，不得静默取其一
- 同一稿件的门户镜像（标题/摘要高度近似、跨站转载）视为同一**转载簇**，只计 1 个独立来源；`多源确认（N 家）` 的 N 按独立稿簇计，不得把镜像当独立信源

#### 4.3 引用编号体系

每条事实性陈述末尾标注 `[编号]`，指向来源索引。编号体系（一 URL 一编号 · 按首次出现顺序分配 ·
图像用 `[图N]` 区分 · 推测可引用但不得包装为事实）的唯一权威见 `report-theme/CONTRACT.md`，
本处不重复。联合态下引注由装配端依 `sources.json` 生成（该工件的字段契约见 CONTRACT-joint §11）。

#### 4.4 来源分级与确定性标记

**来源分级（A/B/C）的唯一权威是 CONTRACT-joint §2**（A=官方一手/本人账号原文 ·
B=权威媒体全文 · C=转载/自媒体/平台样本）。本处不重复定义，因为同名的 A/B/C 曾在多处被写成
不同含义，导致"来源共 86 条 · A 官方 0 条"这类假统计。

要点两条：
- 自动采集帖默认 C；**转载稿按原始出处定级**（"新浪财经转载观察者网"是 B，不因门户而记 C）；
- 分级统计里若出现 `A=0`，而正文确实引用了官媒原文或当事人本人账号原文，说明**分级没落地**，
  要修分类而不是照抄统计行。

**确定性标记**（正文内联，仅用于具体数字/数据）：

| 标记 | 含义 |
|------|------|
| ▲ | 官方渠道确认 |
| ● | 多家独立媒体一致，未经官方文件确认 |
| △ | 单一来源，或不同来源数字有出入 |

所有图像描述默认 △（模型无法视觉验证）；3+ 独立文字来源一致描述同一图像可升级为 ●。
联合态下 ▲●△ 只用于数字口径，不得混入裁决 chip（CONTRACT-joint §3）。

涉及大量数字的汇编，可先用 `{SKILL_DIR}\scripts\extract_stats.py` 从抓取正文/摘要自动提取「数字+单位+上下文」结构化条目，供正文引用与复核（用法见脚本头注释）。

#### 4.5 冲突消解（冲突 → 消解）

数字或说法冲突时，**不只标 △ 罗列各说法**，必须继续分析冲突来源并给出判断：
- **口径差异**：统计口径不同（如"伤亡"是否含轻伤）→ 说明差异，不做强行统一
- **时间差异**：不同时点的数据更新（如"目前 X 人" vs "最新 Y 人"）→ 以最新为准并标注时间
- **立场差异**：不同立场来源的叙述冲突 → 并列呈现，标注各方信源等级
- 分析后给出「**更可信的一方 + 理由**」（依据：信源等级 / 一手 vs 二手 / 独立交叉确认数），措辞用"倾向于""证据支持"，不武断

### 阶段 5：撰写与检查

按输出规范组织报告。完成后做覆盖完整性检查：地域 × 主体 × 议题矩阵逐格核实，明确列出已覆盖/未覆盖项及原因。

同时核对三项汇总质量要求：
- **主题有中心**：每个主题都能一句话说清（4.1 聚类是否成立）
- **冲突已消解**：重复主张已合并（4.2），冲突说法已给出消解分析（4.5），而非仅标 △ 罗列
- **立场已均衡**：对立/少数观点显式覆盖并标注信源稀缺度（见输出规范第 3、6 章）

### 阶段 6：主体档案（可选产出，v0.2.18）

当事件存在 **≥2 个有公开行为或公开主张的参与方** 时，除时间线外再产出一份按主体重投影的档案，落盘 `data/{event_id}/actors.json`，供百宝袋 `build_report.py --actors` 装配为「主体视角档案」小节（挂第二章末，h3 自动编号 x.1）。

**为什么值得做**：时间线回答"发生了什么"，主体档案回答"每一方做了什么、主张了什么、如何回应对方"。争议事件的来龙去脉往往只有把各方行为链并排才看得清（如"甲一年长线研究 vs 乙 88 小时算力冲刺"的对比）。

**主体识别判据**：
- 须有**可指认的公开行为**（发布 / 声明 / 回应 / 裁决 / 明确未回应皆可）——仅"被提及"不列为主体；
- 群体主体（"数学界""监管方""舆论场"）须标为聚合性主体，行为限于可证范围，不得替群体代言。

**分层判据**：
- `layer: "main"`（主轴）＝ 有**多节点行动链**且提出**独立主张**（通常是事件发起方与指控/反对方）；
- `layer: "minor"`（次要）＝ 关联方 / 第三方 / 无独立主张者（供职机构、评审机构、个人表态、媒体转述层）。

**时间子线投影（硬规则：只投影不新增）**：
- 每方节点必须能在本技能已产出的时间线章节找到对应条目；**禁止**在档案里写全局时间线没有的新事实；
- 节点只保留「日期 + 动作短语」的压缩形式，描述性文字留在时间线，避免两处叙事漂移。

**回应链构造**：跨主体的"一来一回"按序写入 `cross` 数组；关系词限事实性动词（指控 / 否认 / 澄清 / 证实 / 回应 / 裁决），不写评价；无定论的一步须用 `tag` 标明（如"证据不足 · 无第三方证据"）。

**schema（`actors.json`）**：

```json
{
  "title": "主体视角档案：各方行动链与主张",
  "topology": "双主轴 + 3 次要 / 线性指控链",
  "span": "2025-09 ~ 2026-09-09",
  "stages": [
    {"name": "背景期", "span": "2025-09 ~ 2026-07"},
    {"name": "触发期", "span": "08-15 ~ 09-01"},
    {"name": "爆发期", "span": "09-05 ~ 09-08", "hot": true},
    {"name": "发酵期", "span": "09-09", "hot": true}
  ],
  "actors": [
    {"name": "OpenAI", "role": "官宣方", "layer": "main",
     "bio": "身份简介 2–3 行：机构属性 + 事件中的位置 + 关键动作摘要",
     "nodes": [
       {"col": 2, "date": "08-28", "text": "开始训练内部新模型", "kind": "act"},
       {"col": 4, "date": "09-08", "text": "官宣给出 NS 解答", "kind": "act"}
     ],
     "claims": [1, 2, 4], "ref": "[1]"},
    {"name": "Anthropic", "role": "关联方 · Alpöge 供职方", "layer": "minor",
     "bio": "…", "nodes": [{"col": 4, "date": "09-09", "text": "无公司层声明", "kind": "quiet"}]}
  ],
  "cross": [
    {"from": "Buckmaster / Alpöge", "rel": "指控", "to": "OpenAI", "tag": "#7 真实"},
    {"from": "OpenAI", "rel": "否认 · 澄清", "to": "Buckmaster / Alpöge", "tag": "#8 部分真实"}
  ]
}
```

**字段要点**：
- `stages` ＝ **离散阶段**（非时间比例）——这是该组件普适性的来源：跨度悬殊（20 年历史背景 vs 1 天爆发）也不失真；表头为「阶段名 + 日期区间」双行，`hot: true` 给活跃列加底色；
- `nodes[].col` ＝ 阶段序号（1-based，推荐）或 `stage` 名称（回退匹配）；`kind ∈ act ●官方行动 / decl ▲声明·发布 / view ○表态·被指行为 / judge ◈裁决·评审 / quiet ┄静默`；
- **静默也要登记**：`kind: "quiet"`（"未见表态""无官方声明"）与空单元格语义不同——前者是已核事实，后者是未覆盖，不得混淆；
- `claims` ＝ **只写第三章断言编号**（`[1, 2, 4]`）；裁决词由装配端从 `facts.json` 登记册自动补齐——**本技能不判定真伪**（需核查 → `/破虚妄`）；
- `bio` 用 2–3 行写清"谁 + 在事件中的位置"，不写评价。

**交付与校验**：交百宝袋装配（`--actors data/{event_id}/actors.json`），装配后由 `check_report.py` 校验（E5 行列数不齐 / W12 空壳主轴 / W13 身份卡与轨道行编号不匹配 / W14 claims 越界）。

### 阶段 7：立场卡组（v0.3，三技能联合任务必产）

针对第六章「舆论观点综合」，把 opinion.py 聚类出的每个立场写成一张**抽象逻辑链**卡，落盘 `data/{event_id}/stance_cards.json`，
供百宝袋 `build_report.py --stance-cards` 装配。

**为什么是抽象逻辑链而不是引语**：装配端原在缺该工件时回退生成「引语卡」——卡内只填高赞原文、不填论证链，
与同章「高赞代表」表逐条同源，同一材料出现两次。本阶段的职责正是补上表格给不出的东西：**这个立场是怎样推出结论的**。

**schema**：

```json
[
  {"name": "立场名", "pct": "69.8% · 143 条", "view": "一句话视角（≤20 字）",
   "steps": ["前提（≤14 字）", "要件/推理", "推论", "代价", "落点"],
   "note": "证据 [1][2][5] · 防呆说明（≤55 字，各卡长度相近）"}
]
```

**硬性限制**（单步字数 / 步骤数 / 引用位置 / `note` 长度 / 卡内不放引语）：唯一权威见
`report-theme/CONTRACT.md`「立场卡组书写限制」，超限由 `check_report.py` W15 提示。本处不列表——
同一组数字曾散在 5 个文件里，改一处忘四处。

**防漂移**：卡内所有数字（占比、条数）必须与 `opinion.json` 一致；`steps` 中的引用编号必须存在于来源索引；
立场不得自创，只能是 opinion.py 聚类出的立场（含少数派——少数派的卡尤其重要，它承载表格表达不出的论证结构）。

## 核心原则

- 搜索摘要（snippet）为默认信息获取方式，抓取仅在摘要不足时使用（策略链见 `references/source-fallback.md`）。
- Python 脚本单次任务 ≤3 次调用，环境未就绪则回退。
- 禁止用外媒中文版替代英文原站；禁止对同一 URL/被阻断域名反复重试。
- **汇总优先于罗列**：重复信息必须合并、冲突必须消解、碎片必须聚成主题。报告的价值在降低读者的认知负担，不在穷尽信源。
- **结论先行**：compile 报告开头必须有「一句话结论 + 3-5 条关键要点」，细节作为证据层跟在后面。
- **立场均衡**：对立/少数观点必须显式覆盖并独立标注，禁止让报告被主流叙事单边化。

## 阶段 6/7 交付的工件（联合态）

联合态下，阶段 1–5 的结论必须落成**工件**交给 ④ 装配；schema 与门禁见 CONTRACT-joint §11：

| 工件 | 内容 | 两种路径 |
|---|---|---|
| `timeline.json` | 事件时间线：`date` 一律 `YYYY-MM-DD`（区间两端带年）；`count`（当日采集数）**缺省由 ④ 回填，不必手写** | 联合态必产；独立态并入报告第 2 章 |
| `sources.json` | 来源索引：`{name, url, grade, type}` + 可选 `fetched_file`（归档正文文件名）/ `used_as`（被哪些断言引用） | 联合态必产；独立态并入来源索引表 |
| `coverage.md` | 覆盖完整性声明：语料口径（原始→分析→剔除量）· 信源结构 · 主体维度 · 地域 · 议题 · 未覆盖项 | 两态均需，联合态由装配端渲染 |
| `viewpoint.md` | 视点综合：声量结构 · 各立场论证 · 少数派 · 焦点转移 · 未识别残留 · 场景推演 | 两态均需 |
| `actors.json` | 主体档案（阶段 6） | 联合态必产（≥2 个有公开行为的参与方时） |
| `stance_cards.json` | 立场卡组（阶段 7） | 联合态必产 |

**两条硬纪律**：
1. **正文里出现的数字（覆盖率、条数、层数）一律引用而不复述**——口径行由 ④ 从 `opinion.json` 生成，
   手写副本必然漂移（实测出现过同一份报告里 521 与 296 并存）。
2. **`sources/` 归档出的正文文件必须在 `sources.json` 的 `fetched_file` 里登记**；
   抓了但未进正文的来源，须在覆盖声明里单列"已获取未引用"——否则归档目录无法回溯，等于白抓。

## 执行环境契约（DSH/Windows）

- 含中文的 Python 脚本不可 `python -c` 内联；先 Write 到 `.py` 文件再执行。
- Python 中文输出一律写 UTF-8 文件后 `read`（避免 stdout GBK 报错）；执行前设 `$env:PYTHONIOENCODING='utf-8'; $env:PYTHONUTF8='1'`。
- 向脚本传 JSON 参数先落盘为 `.json` 文件再传路径（避免 PowerShell 引号吞掉 JSON）。

## 输出规范

### 模式一：信息汇编报告（`compile`）

1. **结论速览** — 一句话核心结论 + 3-5 条关键要点（30 秒读完层，细节见后）
2. **任务概述** — 一句话概括需求和范围
3. **核心内容** — 按主题组织（2-4 个聚类主题，每个主题一句话中心 + 支撑条目）。事实陈述标 `[编号]`，图像标 `[图N]`。原文引用块保留来源名称。确定性标记（▲/●/△）内联于数字之后。**对立/少数观点独立小节**，标注「该立场信源稀缺」或列出其信源及等级
4. **来源索引** — `[编号]` 来源名称、URL、等级（A/B/C）、类型。按首次出现顺序排列
5. **图像附录** — 可选。每项含 `[图N]`、声称内容（snippet/配文描述）、出处、URL、视觉验证状态（默认"未验证 △"）
6. **覆盖完整性声明** — 已覆盖/未覆盖维度，未覆盖项注明原因；含**立场维度**（哪些立场已覆盖、哪些稀缺或缺失）
7. **方法论说明** — 搜索轮次、搜索词设计、来源数、引用主张数、**聚类/去重统计**（原始信源 N 条 → 聚类 M 个主题 / 合并后 P 条）
8. **汇编时间戳** — 信息截止时间、汇编完成时间、事件跨度

### 模式二：事件时间线（`timeline`）

1. 事件概述 → 2. 时间线（日期+描述+`[编号]`）→ 3. 各方反应（按主体分类）→ 4. 关键节点分析 → 5. 来源索引 → 6. 图像附录（可选）→ 7. 汇编时间戳

### 摘要模式（`--summary`）

精简核心内容 + 来源列表。不输出完整章节。

### 格式选项（`--format`）

| 格式 | 输出 | 适用 |
|------|------|------|
| `markdown`（默认） | 报告正文为 Markdown（各模式的默认形态） | 人读、贴入 Obsidian |
| `json` | 结构化 JSON（compile 模式 schema 见下） | 喂给下游 skill 或程序化消费 |

**compile 模式的 `json` schema**：

```json
{
  "title": "报告标题",
  "format": "compile",
  "summary": "一句话核心结论",
  "key_points": ["要点1", "要点2"],
  "topics": [
    {"title": "主题名", "center": "一句话中心",
     "items": [{"text": "事实陈述", "refs": [1, 3], "certainty": "▲"}]}
  ],
  "standpoints": [
    {"side": "立场名", "coverage": "覆盖|稀缺|缺失", "refs": [4, 6]}
  ],
  "sources": [
    {"id": 1, "name": "来源名", "url": "https://...", "grade": "A|B|C", "type": "类型"}
  ],
  "meta": {"search_rounds": 2, "source_count": 8, "merged_count": 6,
           "topic_count": 3, "as_of": "信息截止时间", "compiled_at": "汇编完成时间"}
}
```

json 输出同样必须满足全部汇总质量要求（聚类、去重、冲突消解、立场均衡、结论速览）——schema 只是传输形态，不是质量豁免。

## 注意事项

- **不做真伪判断**：不区分事实与谣言。需核查 → `/破虚妄`
- **信息截止点**：必须标注，注明搜索引擎索引延迟可能遗漏最新信息
- **可追溯信源**：每条事实标 `[编号]`，URL 集中索引。设计目标：正文 +4 字符/条，避免 URL 内联造成 ~30% token 膨胀
- **不确定性坦诚**：数字出入不做强行统一，标 △ 列各说法；但 △ 之后必须给出冲突来源分析（口径/时间/立场）与更可信一方的判断（见 4.5），不得止步于罗列
- **立场均衡**：对立/少数观点显式覆盖并标注信源稀缺程度，防止报告被主流叙事单边化
- **汇总质量自检**：交付前核对——重复已合并、冲突已消解、主题有中心、结论有速览；做不到的在「覆盖完整性声明」中显式说明
- **搜索节制**：两轮以内。本技能价值在**整理**，穷尽不如清晰
- **与 `/破虚妄` 关系**：`/破虚妄` ="这事是真的吗"，`/揽风云` ="关于这事都有哪些说法"
- **与 `/百宝袋`、`/破虚妄` 关系（三技能联合汇编）**：遵行 `~/.dsh/report-theme/CONTRACT-joint.md`（§11 工件契约 ·
  §2 来源分级 · §8 主体档案 · §9.2 立场卡组）；本技能在采集完成后承担信息聚类、冲突消解与来源索引部分。
  细则以契约文件为准，本处不重复。
- **事件进行中**：不下确定性结局/走势判断，只作情景表述（如"若官方不回应则 X；若继续发文则 Y"），并注明为动态快照（情景句与时效规则见 CONTRACT-joint §5）。
