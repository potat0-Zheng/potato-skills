# 判风潮 · 编码手册（codebook）

> **版本**：v0.7（与脚本同版）· **地位**：判风潮内部**判读标准与词典构造的唯一出处**。
> **关系**：四层口径（A/B/C/D）的定义**不在本手册**，以 `~/.dsh/report-theme/CONTRACT-joint.md §9.1` 为唯一权威，本手册只写**§9 未覆盖的判读与构造方法**；命令与字段速查见 `../SKILL.md` §6–§7。
> **用法**：构造或修订立场词典前、判读边界案例前、报出结论前，先读本手册对应小节。改本手册＝改判读标准，须在 §9 记一行变更。

---

## 0. 定位

本手册回答四个问题：

1. **什么算立场**（§1）——避免把"情绪"或"话题"当成立场；
2. **哪些记录进分母**（§2）——分母定义错了，后面所有百分比都错；
3. **怎么造词典、造到什么程度算够**（§3、§6）；
4. **人工判读时怎么判对错**（§4、§5）——这是抽检结论可信度的源头。

不回答：怎么跑脚本（见 SKILL.md）、口径的权威定义（见 CONTRACT-joint §9.1）、报告怎么写（归 ④ 百宝袋装配端）。

## 1. 什么叫"立场"

**立场 = 对事件中某个可争辩主张的站位**（支持/反对/归因于谁/要求谁做什么）。它必须能被**另一个人的相反表述**所对立，例如"应加装电梯"对"不应加装电梯"。

| 概念 | 区别 | 例（同一事件） | 本 skill 是否处理 |
|---|---|---|---|
| **立场** | 对主张的站位 | "支持加装，老人上下楼太难" | ✅ 只做这个 |
| **议题/话题** | 讨论的对象，不带站位 | "电梯加装" | ❌ 只作聚类线索 |
| **态度/情绪** | 正负情绪强弱 | "太离谱了""气死了" | ❌ 不做情感极性（无独立抽检口径） |
| **事实主张** | 可裁决真假 | "方案表决未通过" | ❌ 归 ③ 破虚妄 |

**操作判据（一句）**：把这条记录给一个持相反看法的人看，他会不会觉得"这人在跟我对着干"？会 → 立场；不会（只是在讲事实、发泄情绪、闲聊、提问）→ 不是立场。

> 注意：**"未识别"只表示词典没命中，不表示与事件无关**——相关性在上游 `relevance_gate.py` 已经判过。

## 2. 谁进分母、谁不进

四层的定义见 CONTRACT-joint §9.1；本节只写**操作判据**（这是 §9 未覆盖的部分）：

| 层 | 操作判据 | 常见误判 |
|---|---|---|
| **A 个人表达（分母）** | 账号为个人号 **且** 内容含立场表达 | 把机构帖算进来 → 分母被"报道了某立场"污染 |
| **B 机构帖（不进分母）** | **仅按账号名机构特征词**判定（`opinion.py` 内置后缀/成词/匿名化正则三档） | 把"网友A/报料人/都市丽人"这类昵称判成机构帖 → 真实舆论主体被踢出分母（v0.5 已修：单字后缀必须位于账号名尾部且账号名 ≥3 字） |
| **C 未识别残差** | 词典零命中的个人 UGC；再机械拆为「纯反应」「原样转述」「未分类」 | **不得**把整段称为"不含立场表达"——只有"未分类"段需人工核 |
| **D 治理剔除** | 上游剔除条数；**未传 `--total-raw` 时输出 `null`（未知），不得写成 0** | 把"没传参数"读成"没有剔除" |

**两条硬纪律**
1. **B 层是识别下界**：平台会匿名化账号名（`潇***报`），漏判本来就会发生；**宁可偏小（保守），不可偏大（污染分母）**。B 层占比 >15% 时脚本会告警，须人工确认判定是否过宽。
2. **未识别层不得画进占比、不得当成一个立场**；它的规模与构成只能用抽检估计并并排披露。

## 3. 立场体系构建四步

### 步骤 1 · 立场枚举
- 依据：① 治理后语料 + ② 首轮搜索的观点分歧（**三组词都要实跑**：指控方口径 / 被指控方口径 / 中性口径——只跑一组会让占比系统性偏向一侧）。
- 产出：3–8 个候选立场名。**命名规则**：写"站位 + 争点"，别写"正方/反方"（后者在报告里无法自证）。

### 步骤 2 · 词典构造
- 每个立场 3–10 个词，全部满足**单方特征**：只会在该立场出现（"支持加装"/"一楼反对"），而不是两派共用的中性词（"电梯""小区""物业"）。
- `re:` 前缀用于正则，使用边界：**只用于形态固定、字面稳定的模式**（如 `re:支持.{0,4}加装`），不要用它做语义判断；正则命中数越多不代表越准，规则层误判率实测 2–3 成。

### 步骤 3 · 词频预检（**必须先做**）
跑一轮 `opinion.py` 后看三个字段，逐条处置：

| 字段 | 含义 | 处置 |
|---|---|---|
| `dictionary_quality.zero_hit_keywords` | df=0 的词（语料里从未出现） | 删除或改写；**最常见来源是凭空想象的词** |
| `vocabulary_advice.candidate_terms` | 词表外高频字 n-gram，附最接近的现有词与相似度 | 相似度 ≥0.5 视为**变体**（并入或替换）；低相似度视为**新表达**（人工判读后再决定是否立新立场） |
| `candidates.clusters` | 词表外的成簇表达（种子词 + 规模 + 样例） | `suspected_unnamed=true` 的簇必须人工看样例：可能是一个**没被命名的立场** |
| `dictionary_quality.doc_frequency` | 每个词的命中文档数 | 命中过高的词（如覆盖 >30% 语料）多半是中性泛词，应剔 |

### 步骤 4 · 上限与止损
- **词典修订至多一次**（改一次后重跑；仍不达标就走 §6 的标注层路径，**不得改分母、不得改成"方向性参考"**）。
- 每次修订必须留痕：`python scripts/vocab.py --diff 旧.json 新.json --corpus 语料.jsonl`（新增/删除/改名 + 新增词在语料里的 df）。

## 4. 判读口径：三种核怎么判

抽检判读的问题与判据（脚本里的 `_q` 就是下表）：

| 核 | 问题 | 要填的字段 | 判"对"的标准 |
|---|---|---|---|
| `stance` | 这条真的属于「X」吗？ | `verdict=对/错` | 该记录**表达了该立场**（不要求在字面上重复立场词） |
| `rule` | 规则命中项：这条真的属于「X」吗？ | `verdict=对/错` | 同上；注意规则层只命中"像"某种立场的表述，误判率高是预期 |
| `unclassified` | 这条含立场表达吗？ | `has_stance=true/false` + `stance` | 含 → 必须写立场名（用现有立场名；确实不属于任何现有立场 → 写"其他：<你的概括>"，并在结论里说明） |

**三条判读纪律**
1. **逐条判，不许跳**：core（代表性样本）必须全部判完，否则 `--apply` 失败（脚本不产出部分结果）；enrich（富集）可留空，但不判就得不到"机器最容易错在哪类"的对照。
2. **判"记录本身"，不判"作者"**：同一作者的其他发言不作为本条的依据。
3. **拿不准就写进 `note`**：`note` 会随误判样例保留在工件里，供仲裁与后续修订（这也是 codebook 演进的原料）。

## 5. 边界案例处置

| 情形 | 判定 | 理由 |
|---|---|---|
| **反讽**（"支持加装？呵呵，先看看一楼的采光吧"） | 按**字面相反的立场**判（此例判"一楼反对"），不是按命中词判；但**脚本不会自动改判**，只给 `irony_suspect` 标记（线索：引号包裹/反问句式/嘲讽用词/夸张标点/转折反转）提示你复核 | 反讽需要人的语义判断；自动改判会同时污染标签与误判率 |
| **否定修饰**（"我不反对加装，但…"） | 看**整句落点**：转折后的分句才是立场；只有命中词被否定词紧邻前置时，脚本才给 `negated` 标记 | 同上：标记≠改判 |
| **一条含多个立场**（"加装是好事，但一楼采光也该补偿"） | 判**主立场**（作者更倾向哪边）；脚本是单标签口径，多标签属阶段二 | 单标签口径下，占比之和才等于 100% |
| **纯情绪/玩梗**（"哈哈哈""吃瓜""就这"） | **不含立场表达**（`has_stance=false`） | 没有可对立的站位 |
| **事实转述**（"据报道，方案表决未通过"） | **不含立场表达**；若为机构/媒体号则由 B 层剔除 | 信息供给 ≠ 立场表达 |
| **提问**（"有没有人知道补贴政策？"） | 不含立场表达；**但**若问句本身预设了立场（"为什么非要强推？"）则按预设判 | 看是否隐含站位 |
| **提问式反讽**（"难道采光不是人家的权利吗？"） | 含立场（判"一楼反对"） | 反问句表达的是与字面相反的确定主张 |
| **地域/人身攻击，无站位** | 不含立场表达（可能属治理层噪声） | 攻击 ≠ 立场 |
| **与事件相关但无站位**（"我们小区也搞过，最后没成"） | 不含立场表达；**不得**因此说它"与事件无关" | 相关性与立场是两件事 |
| **机构/媒体帖**（在 unclassified 池里出现） | 不该出现——机构帖已被排除在所有抽检池外；若出现说明池不同源（`--institutional` 未透传），脚本会硬失败 | 口径一致性 |
| **同源文本**（多账号发同一段话） | 判**文本本身**是否含立场；同源只作结构披露（跨账号同源值得人工核），**不得**据此判"水军" | 转述新闻也会同源 |

## 6. 覆盖目标与止损

| 指标 | 目标/阈值 | 不达标怎么办 |
|---|---|---|
| `coverage_rate`（A / 全部语料） | 报告里必须披露；低于 `coverage_target`（默认 70%）时**不得写"主流/压倒性"** | 按上述四步修订词典（**至多一次**） |
| `coverage_of_judgeable`（A / 可判集合，契约口径） | 与上面并排披露 | 同上 |
| `coverage_of_judgeable_norule`（去掉规则层依赖） | **跨报告比较用这个**（同语料同值） | — |
| 抽检误判率 | 每立场 ≤ `error_rate_max`（默认 30%） | 超限的立场 `usable_as_main=false`，**不得作主结论** |
| 编码信度 | κ/α ≥0.667 可用；<0.4 须先改判读标准 | 不一致条目**先仲裁、写进本手册 §4/§5，再重跑**；不得取两人平均 |

**词典修订用尽仍不达标时的唯一合法路径**：走**标注层路径**（用外部 LLM 标注或人工全量标注作为并列层，`--llm-labels` 导入），并如实披露"这是标注层结果、未抽检前只作上界"。

## 7. 结论边界（措辞纪律）

机器依据见 `../SKILL.md` §7 的红线表；本节给**判断规则**：

1. **覆盖率不足** → 只能说"在已识别的 N 条里，X 占 a%"，不能说"多数人""主流""压倒性"。
2. **有效日不足**（`selfcheck.trend_claim_forbidden=true`）→ 不得出现"走势/转向/走高/回落"；只能写单时点结构。
3. **两个立场/群体之差** → 必须看 `stance_comparisons[].verdict`：区间跨 0 就写"两者差异不显著（区间跨 0，不得声称有差异）"。
4. **占比是条数结构** → 必须与人数口径并排（`author_distribution`、条·人比、HHI）：声量集中度高时，条数占比读不出"多少人这么想"。
5. **未识别层** → 必须给出"约 N 条含立场表达"的估计（含区间）与"故本章占比应读作已识别部分内的结构"这句限定。
6. **变点/事件对齐** → 变点只说"结构在此日前后不同"，不说"因为某事件"；事件对齐的 `caveat` 必须原样保留。
7. **LLM/规则层** → 抽检前一律读作**占比上界**，不得单独下判断。

## 8. 已知限制（诚实标注：本手册不含）

- **抽样设计**：现在是"平台 × 点赞档 × 时间箱"的**分层配额抽样**，不是概率抽样；估计用后分层加权 + Wilson/Newcombe 区间，**不做总体概率推断**（不给"全体网民的立场分布"这种结论）。
- **多标签/主次立场**：单标签口径（命中数最多者胜、平票按词典顺序）；多标签属阶段二（需改 CONTRACT §9.1）。
- **跨事件基线**：不做"比同类事件高/低"的判断（无历史基线口径）。
- **平台分层权重**：按平台分层做估计，但**不按平台活跃用户规模加权**（平台间不可直接比较）。
- **组织化行为/水军**：只做**结构披露**（同源文本、发文集中度 HHI、高频账号），**不判定、不剔除**。
- **账号可信度**：不评估账号历史与真实性。
- **判读主观性**：立场判读天然有主观成分，本手册的作用是**把分歧显性化**（κ/α + 仲裁），不是消除它。
- **语料偏差**：平台抽样偏差、时间窗偏差、爬取覆盖偏差均由上游造成，本 skill 只能披露、不能修正。

## 9. 版本与变更纪律

| 变更类型 | 是否改口径 | 必须做什么 |
|---|---|---|
| 改 `stances.json`（增删改词、新增立场） | **是**（占比、覆盖率都会变） | `vocab.py --diff` 留痕 → 重跑 `opinion.py` → 重跑 `--make`/`--apply`；在报告里说明"词表版本已变" |
| 改本手册的判读标准（§4/§5） | **是**（误判率可比性失效） | 在本表记一行；解释性用例若已仲裁出结论，追加到 §5 |
| 改 `config.json` 阈值 | 否（只改告警线） | 无；工件里 `thresholds.sources` 会显示来源 |
| 改脚本方法 | 可能 | 用 `opinion.py --prev` 出漂移报告，确认变动项并在报告里披露 |
